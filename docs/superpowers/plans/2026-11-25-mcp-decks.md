## Global constraints

- The TypeScript is the behaviour of record. **Nothing in `packages/ui/features/decks/validation/`,
  `stats/`, `DeckStats.tsx`, `deckBuckets.ts`, `openingHand.ts` or `packages/ui/lib/mana.ts`
  changes.** The only TypeScript added is the golden suites under
  `packages/ui/features/decks/golden/`.
- A golden is written by TypeScript (`pnpm exec vitest run -u <file>`, through
  `toMatchFileSnapshot`) and never edited by hand. A Rust answer that disagrees is the Rust's bug.
- The core gains no dependency (no `regex`). Every regular expression is a hand-written matcher.
- No platform cfg, clock, I/O or thread outside `src/platform/` (the core's fences).
- New core commands are `read` entries in `crates/grimoire-core/src/commands.rs` and `TABLE_ONLY`
  rows in `apps/desktop/src-tauri/src/command_table.rs`. A `TABLE_ONLY` name must not be a
  `fn <name>(` anywhere under `apps/desktop/src-tauri/src/`.
- Multi-line Rust strings: `concat!`. Files in tests: `crate::scratch::path`.
- Per task, run only that task's tests by name filter. `pnpm verify` once per PR, at its end. Format
  with `cargo fmt -p <crate>`, never `--all`.
- Commits: Conventional Commits, ending with the session's `Co-Authored-By` and `Claude-Session`
  lines.

## Shared formats (fixed in Task 1, used by every later task)

**A golden file** (`packages/ui/features/decks/__golden__/<name>.json`):

```json
{
  "about": "<one sentence: which TS suite writes it, which Rust suite reads it, never by hand>",
  "base": { "...": "fixtures.card()'s default DeckCard, row id 0" },
  "specs": { "<key>": { "...": "a FormatSpec" } },
  "cases": [
    { "name": "<unique>", "cards": [ { "<only the fields that differ from base>": "..." } ], "...": "inputs and answers" }
  ]
}
```

- `cards` entries are **overrides of `base`**: a card is `{ ...base, ...override }`. `id` is always
  written (row ids matter to `validateForMarks`).
- `specs` is present where cases name a spec by key.
- Written by `golden/golden.ts`' `goldenText(about, cases, specs?)` (stable two-space JSON with a
  trailing newline); read in Rust by `crate::deck_golden` (`#[cfg(test)]`): `load(text)`,
  `cards(&case["cards"], &base) -> Vec<DeckCardRow>`, `spec(&golden, key) -> FormatSpecRow`, and
  `same(&actual, &expected) -> bool`, which compares JSON with numbers equal by `f64` value (JS
  writes `1` for `1.0`) and is otherwise exact.

**`ValidationIssue`** (`deck_rules::issue`): `severity` (`"error"`/`"warning"`), `code`, `message`,
`card_ids: Option<Vec<String>>`, `row_ids: Option<Vec<i64>>`; camelCase; `None` fields skipped —
exactly the TypeScript shape.

## Review focus

1. **A colourless commander** — `commander_identity` is `Some(empty)`, not `None`: every coloured
   card is outside it. Golden case in Task 4.
2. **A switched-on Maybeboard** counts toward size and identity; a switched-off pile counts toward
   nothing but its own `parked` findings. Golden cases in Task 4.
3. **`unspecified`** answers no issues and `checked: false`, never "legal". Task 7.
4. **Islands are not lands** — `\blands\b` in the bracket grep. Golden case in Task 5.
5. **Floating point** — averages, prices and odds bit-identical to JavaScript. Tasks 3 and 6.
