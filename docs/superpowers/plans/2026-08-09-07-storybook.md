# Storybook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Storybook workbench and catalogue covering every visual state of all 30 React components, driven by a stateful in-memory fake of the Tauri backend.

**Architecture:** Three Vite aliases in `.storybook/main.ts` replace `@tauri-apps/api/core`, `@tauri-apps/api/event` and `@/lib/images` — no component or app source changes. The fake `invoke` dispatches to handlers over an in-memory store of **table rows**, deriving DTOs the way Rust does. Stories select a seeded dataset and an optional fault through `parameters.fake`; card art is a synthetic SVG data URI by default, with a toolbar global that swaps to real Scryfall art.

**Tech Stack:** Storybook 10.5.7 (`@storybook/react-vite`, `addon-a11y`, `addon-docs`), React 19, Vite 7, TypeScript 6, Tailwind 4, Vitest 4.

**Spec:** `docs/superpowers/specs/2026-08-09-storybook-design.md`

## Global Constraints

- **No component source may be edited to make it storyable.** If a component cannot be storied without changing it, stop and raise it as a finding. This is a hard fence.
- **No card images are committed.** Synthetic art is generated at runtime; real art is fetched from `cards.scryfall.io` only under the toolbar global.
- Storybook packages pin to `10.5.7`. TypeScript stays on `6.0.x`.
- `npm run verify` must pass at the end of every task. It is `npm run build && npm run lint && npm run test:run && cargo test --manifest-path src-tauri/Cargo.toml`.
- `eslint` runs `--max-warnings 0`. Stories must be warning-clean, not merely compiling.
- Commit after every task with a conventional-commit prefix (`feat:`/`fix:`/`chore:`/`test:`/`docs:`).
- `format_specs_list` is served from the existing `SPECS` in `src/features/decks/validation/fixtures.ts`. **Never write a second copy of that table.**
- Every fake handler's DTO shape is `src/lib/ipc.ts`. When they disagree, `ipc.ts` wins.
- The app is dark-only. Never add a light theme to the Storybook canvas.

- [ ] **Step 2: Write `.storybook/main.ts`**

The three aliases go in `viteFinal`. **Order matters and the `@/lib/images` entry must come before the `@` entry** — Vite walks the alias array in order and `@` would otherwise swallow it.

```ts
import type { StorybookConfig } from "@storybook/react-vite";
import { fileURLToPath } from "node:url";

const fake = (name: string) => fileURLToPath(new URL(`./fake/${name}`, import.meta.url));

const config: StorybookConfig = {
  stories: ["../src/**/*.stories.tsx", "../.storybook/**/*.mdx"],
  addons: ["@storybook/addon-docs", "@storybook/addon-a11y"],
  framework: { name: "@storybook/react-vite", options: {} },
  viteFinal: (config) => {
    config.resolve ??= {};
    // An array, not an object: these are exact-match rules and their order is the
    // contract. `@/lib/images` must be tried before the bare `@` prefix.
    config.resolve.alias = [
      { find: /^@tauri-apps\/api\/core$/, replacement: fake("core.ts") },
      { find: /^@tauri-apps\/api\/event$/, replacement: fake("event.ts") },
      { find: /^@\/lib\/images$/, replacement: fake("images.ts") },
      { find: /^@\//, replacement: fileURLToPath(new URL("../src/", import.meta.url)) },
    ];
    return config;
  },
};

export default config;
```

- [ ] **Step 6: Type-check `.storybook` in a program of its own**

**Not** by adding it to the root `include`. `.storybook/main.ts` is Node code (it imports
`node:url`) while everything under `src/` runs in a webview, and ambient types are global to
a *program* — one program for both means the app can see `process`, and `setTimeout` starts
returning `NodeJS.Timeout` instead of `number`.

Root `tsconfig.json` keeps `"include": ["src"]` and gains `"types": []`. Add
`.storybook/tsconfig.json` extending it with `"types": ["vite/client"]` and
`"include": ["**/*"]`. Make `build` run both:

```json
"build": "tsc && tsc -p .storybook && vite build",
```

**`"types": []` is the second lock, not the first.** It blocks only the *automatic*
inclusion of `node_modules/@types/*`; a transitive `/// <reference types="node" />` inside a
dependency's own declarations walks straight past it. Measured 2026-08-09: with
`@types/node` merely present in the tree, `vitest` (imported by every test under `src/`) and
`vite` (imported by `src/lib/iconFont.ts`) each dragged it into the app program *despite*
that line — `process.env.FOO` type-checked clean in webview code and three existing
`ReturnType<typeof setTimeout>` handles silently became `NodeJS.Timeout`.

**The fence that actually holds is that `@types/node` is not installed.** Declare the one
function `main.ts` needs in `.storybook/node-url.d.ts`, ambient to the Storybook program
only. **Later tasks must not reinstall `@types/node`.**

```ts
/**
 * The fake `invoke`, aliased over `@tauri-apps/api/core` for Storybook only.
 *
 * It sits *under* `src/lib/ipc.ts` rather than replacing it, so every story exercises the
 * hand-written Rust mirror as well as the component. `ipc.ts` is the file that can drift
 * silently from `#[serde(rename_all = "camelCase")]` structs, and a fake that replaced it
 * would prove nothing about it.
 *
 * Handlers are registered rather than imported so this module stays a dispatcher with no
 * knowledge of the data — `db.ts` owns that, and a story's seed swaps it wholesale.
 */
export type CommandHandler = (args: never) => unknown;

let handlers: Record<string, CommandHandler> = {};

export function registerCommands(next: Record<string, CommandHandler>): void {
  handlers = { ...handlers, ...next };
}

/** Drop every handler. The per-story decorator calls this before re-seeding. */
export function resetCommands(): void {
  handlers = {};
}

/**
 * Rejects with an `Error`, which is what the *IPC layer* throws. A Rust command's own
 * refusal is a bare string (all commands return `Result<_, String>`) — a handler models
 * that by throwing an `Error` whose message is the string, because `ipcError` renders
 * both and the distinction is invisible past it.
 */
export async function invoke<T>(cmd: string, args?: Record<string, unknown>): Promise<T> {
  const handler = handlers[cmd];
  if (!handler) throw new Error(`No fake handler registered for command "${cmd}"`);
  return (await (handler as (a: unknown) => unknown)(args ?? {})) as T;
}
```

```ts
/**
 * The fake `listen`, aliased over `@tauri-apps/api/event`.
 *
 * Two events reach the frontend: `sync:progress` (`SyncProgress`, `useSyncProgress`) and
 * `collection:reconciled` (`useSyncInvalidation`). A story drives either with `emitFake`.
 */
type Listener = (event: { payload: unknown }) => void;

const listeners = new Map<string, Set<Listener>>();

export async function listen<T>(
  event: string,
  cb: (e: { payload: T }) => void,
): Promise<() => void> {
  const set = listeners.get(event) ?? new Set<Listener>();
  listeners.set(event, set);
  set.add(cb as Listener);
  return () => set.delete(cb as Listener);
}

/** Emit to whoever is listening. Nothing queues: Tauri drops events with no listener too. */
export function emitFake<T>(event: string, payload: T): void {
  for (const cb of listeners.get(event) ?? []) cb({ payload });
}

export function resetListeners(): void {
  listeners.clear();
}
```

```tsx
import { useMemo } from "react";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import type { Decorator, Preview } from "@storybook/react-vite";
import { registerCommands, resetCommands } from "./fake/core";
import { resetListeners } from "./fake/event";
import { allHandlers } from "./fake/db";
import { seed, type SeedName } from "./fake/seeds";
import { useAppStore } from "../src/lib/store";
import type { Fault } from "./fake/db";

// Captured once, before any story runs. `useAppStore` is a module singleton and has no
// reset of its own; the actions live in the state object, so replacing state wholesale
// (zustand's second argument) restores them along with the fields.
const PRISTINE_STORE = useAppStore.getState();

const withFake: Decorator = (Story, context) => {
  const { seed: name = "starter", fault = null } = (context.parameters.fake ?? {}) as {
    seed?: SeedName;
    fault?: Fault | null;
  };

  // `useMemo` rather than an effect: the handlers must be registered before the story's
  // first render, or its first query fires against an empty dispatch table.
  useMemo(() => {
    resetCommands();
    resetListeners();
    const db = seed(name);
    db.fault = fault;
    registerCommands(allHandlers(db));
    useAppStore.setState(PRISTINE_STORE, true);
  }, [name, fault]);

  // A fresh client per story. `src/lib/query.ts` exports a singleton, and shared across
  // stories it leaks one story's cache into the next — "empty collection" would render
  // the previous story's rows.
  const client = useMemo(
    () => new QueryClient({ defaultOptions: { queries: { staleTime: 30_000, retry: false } } }),
    [name, fault],
  );

  return (
    <QueryClientProvider client={client}>
      <Story />
    </QueryClientProvider>
  );
};
```

```ts
 * **The re-export must name the real module by a relative path.** `@/lib/images` is what

 *
 * The constants stay real: a frame at the wrong ratio is the one thing a card workbench
 * must not show, and `imageOrigin`'s platform rule is pinned by a test this has no
 * business restating.
 */
export * from "../../src/lib/images";
import type { ImageVariant } from "../../src/lib/images";
import { CARDS } from "./cards";

/** `Variant::dimensions` in `src-tauri/src/images.rs`. */
const SIZE: Record<ImageVariant, [number, number]> = {
  thumb: [146, 204],
  grid: [488, 680],
  display: [745, 1040],
  art: [626, 457],
};

let mode: "synthetic" | "live" = "synthetic";
export function setArtMode(next: "synthetic" | "live"): void {
  mode = next;
}

export function cardImageUrl(cardId: string, face: number, variant: ImageVariant): string {
  const card = CARDS.find((c) => c.id === cardId);
  if (mode === "live" && card) {
    const url = variant === "art" ? card.artCropUrl : card.normalUrl;
    if (url) return url;
  }
  const [w, h] = SIZE[variant];
  const label = card ? card.name : "Unknown card";
  const sub = card ? `${card.setCode.toUpperCase()} · ${card.collectorNumber}` : cardId.slice(0, 8);
  const svg = `<svg xmlns="http://www.w3.org/2000/svg" width="${w}" height="${h}" viewBox="0 0 ${w} ${h}">
  <rect width="100%" height="100%" fill="#1c1a17"/>
  <rect x="2" y="2" width="${w - 4}" height="${h - 4}" fill="none" stroke="#3a352d" stroke-width="2" rx="8"/>
  <text x="50%" y="46%" fill="#cfc7b8" font-family="serif" font-size="${Math.round(w / 14)}"
        text-anchor="middle">${escapeXml(label)}</text>
  <text x="50%" y="56%" fill="#8a8272" font-family="monospace" font-size="${Math.round(w / 22)}"
        text-anchor="middle">${escapeXml(sub)}${face === 1 ? " · back" : ""}</text>
</svg>`;
  return `data:image/svg+xml;charset=utf-8,${encodeURIComponent(svg)}`;
}

function escapeXml(s: string): string {
  return s.replace(/[<>&"']/g, (c) =>
    ({ "<": "&lt;", ">": "&gt;", "&": "&amp;", '"': "&quot;", "'": "&apos;" })[c]!,
  );
}
```

```tsx
 * under the new card's name for the length of the fetch.
 */
export const SwapCard: Story = {
  args: { src: "", alt: "" },
  render: () => {
    const [i, setI] = useState(0);
    const card = i % 2 === 0 ? first : second;
    return (
      <div className="flex flex-col items-start gap-3">
        <CardImage src={cardImageUrl(card.id, 0, "grid")} alt={card.name} width={244} />
        <p className="font-mono text-sm text-text">{card.name}</p>
        <button className="rounded border border-border px-3 py-1 text-sm" onClick={() => setI(i + 1)}>
          Swap card
        </button>
      </div>
    );
  },
};

/** A `src` that will never resolve. The `alt` is what a reader gets, which is why it is
 *  required rather than optional. */
export const FailedLoad: Story = {
  args: { src: "mtgimg://localhost/grid/does-not-exist/0", alt: "Lightning Bolt", width: 244 },
};

/** `alt=""` for a frame whose caption already names the card — a decision, not an omission. */
export const Decorative: Story = {
  args: { src: cardImageUrl(first.id, 0, "art"), alt: "", width: 313 },
};
```

network fetch the difference is visible to the eye.

**Spec coverage.** Every section maps to a task: the three seams → Tasks 1, 2, 7; rows-not-DTOs
→ Task 4; seeds and faults → Task 6; art → Task 7; per-story isolation → Task 6; the dark
canvas → Task 1; Tier 1 → Tasks 8–9; Tier 2 → Tasks 10–12; Tier 3 → Tasks 13–15; the docs
page → Task 16; the five config integrations → Tasks 1 and 2; testing → Tasks 4, 5 and 17.

**Two things the spec named that needed a home and now have one:** the `vitest` `include`
widening is Task 2 Step 1 (it must precede the first `.storybook` test, not arrive with the
tests that need it), and the a11y pass is Task 17 rather than being spread across every
story task, so violations are triaged against one another.

**Deliberate deviation from bite-sized granularity.** Tasks 8–15 enumerate story names and
args rather than spelling out ~128 story bodies. Task 8 Step 1 is a complete worked file and
is the template for all of them; every later step names each story and its exact args. Writing
all 128 bodies here would make the plan longer than the code it describes and would go stale
the moment a prop changed. Where a component's props are substantial (Task 10), the plan says
**read the component first** rather than guessing a shape.

**Type consistency.** `FakeDb`, `FakeCard`, `FakeEntry`, `FakeWish`, `FakeDeck`,
`FakeDeckCard`, `Fault`, `SeedName` are defined in Tasks 3, 4 and 6 and used under those
names throughout. `registerCommands`/`resetCommands`/`invoke` (Task 2) match their uses in
Task 6. `readHandlers`/`writeHandlers`/`allHandlers` are introduced in Tasks 4 and 5 and
`allHandlers` is what Task 6's decorator calls. `setArtMode` (Task 7) matches its call in
Task 7 Step 2.
