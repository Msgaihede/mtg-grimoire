# Home Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A customizable home page — the app's landing view — carrying six widgets for shortcuts,
collection and wishlist price breakdowns, and a recent-actions feed grouped by day.

**Architecture:** One new `ViewId` and `NAV` row; one `app_meta` row holding a layout document whose
widget *vocabulary* lives in TypeScript; six new read commands, each in the module its data lives
in; and one new `activity` table (schema v43) that a `activity::record()` helper writes and an
`activity_recent` command reads UNIONed with the existing `deck_audit`.

**Tech Stack:** Rust/rusqlite/Tauri 2.11, React 19, TypeScript 6, TanStack Query, `@dnd-kit` 0.5.0,
Tailwind v4, Vitest, Storybook.

**Spec:** `docs/superpowers/specs/2026-09-10-home-page-design.md` — read it before Task 1. The plan
argues from it and does not restate its reasoning.

## Global Constraints

- **Work in this worktree only:** `D:\Code\mtg-grimoire\.claude\worktrees\home-page`, branch
  `worktree-home-page`. Never `cd` to the repo root.
- **Subagents do not run tests and do not commit.** A slice compiles against a tree its siblings are
  still changing. Each reports what it changed; the lead runs `npm run verify` after fan-in and
  makes the commit. `npm run verify` is never run twice at once.
- **File ownership is exclusive per wave.** Two agents editing one file clobber each other. Every
  task below lists the files it owns; a file appears in exactly one task per wave.
- **User schema head is 42** (`schema.rs:372`). The activity table is **v43** — re-check
  `USER_SCHEMA_VERSION` against `origin/main` immediately before opening the PR, because a parallel
  branch taking v43 first is a collision no build catches.
- **Never install `@types/node`.** Never add a dependency.
- **`cards.price_usd` / `price_eur` are a display fallback chain and are never summed.** Every price
  goes through `crate::sorting::price_expr` or its siblings.
- **A new command goes in the module its data lives in, with `#[cfg(not(target_family = "wasm"))]`
  on the wrapper**, never on the module. `search.rs` is the pattern.
- **Rust supplies facts; TypeScript draws conclusions.** No sentence, no widget vocabulary and no
  `ViewId` may appear in Rust.
- **Money on screen is `formatPrice(value, currency)` + `pricesAsOf(marketplace)`.** A `null` price
  is an em dash, never another marketplace's number.
- **Dim text is `text-dim`, never `text-muted`.** Z-indexes come from `LAYER` and nowhere else.
  Motion timings come from `src/lib/motion.ts` and nowhere else. Tailwind classes are written whole
  — an interpolated class emits no rule.
- **Commit style:** `feat:` / `fix:` / `chore:` / `test:` / `docs:`, small, one per task group.

## The wire, fixed up front

Every task below is written against these exact types. They are the contract between the Rust
tasks, the `ipc.ts` task and the UI tasks, which run in different waves and cannot see each other.

**Rust (serde `rename_all = "camelCase"`), TypeScript mirror in `src/lib/ipc.ts`:**

```rust
// home.rs
pub struct HomeWidget { pub id: String, pub kind: String, pub span: u8, pub config: serde_json::Value }
pub struct HomeLayout { pub version: u8, pub widgets: Vec<HomeWidget> }

// wishlist.rs
pub struct WishlistSummary { pub wishes: i64, pub copies: i64, pub cost: f64, pub unpriced: i64 }

// collection.rs and wishlist.rs
pub struct BreakdownRow { pub key: String, pub name: Option<String>, pub cards: i64, pub value: Option<f64> }

// deck.rs
pub struct DeckValue { pub deck_id: i64, pub value: Option<f64>, pub unpriced: i64 }

// activity.rs
pub struct ActivityEntry {
    pub id: i64, pub at: i64, pub scope: String, pub kind: String,
    pub deck_id: Option<i64>, pub card_id: Option<String>, pub card_name: Option<String>,
    pub payload: String, pub delta: i64,
}
```

```ts
// src/lib/ipc.ts
export interface HomeWidget { id: string; kind: string; span: number; config: unknown }
export interface HomeLayout { version: number; widgets: HomeWidget[] }
export interface WishlistSummary { wishes: number; copies: number; cost: number; unpriced: number }
export interface BreakdownRow { key: string; name: string | null; cards: number; value: number | null }
export interface DeckValue { deckId: number; value: number | null; unpriced: number }
export interface ActivityEntry {
  id: number; at: number; scope: string; kind: string;
  deckId: number | null; cardId: string | null; cardName: string | null;
  payload: string; delta: number;
}

homeLayout: () => invoke<HomeLayout>("home_layout"),
setHomeLayout: (layout: HomeLayout) => invoke<void>("set_home_layout", { layout }),
startView: () => invoke<string>("start_view"),
setStartView: (view: string) => invoke<void>("set_start_view", { view }),
wishlistSummary: (marketplace: MarketplaceId) => invoke<WishlistSummary>("wishlist_summary", { marketplace }),
collectionBreakdown: (dimension: string, marketplace: MarketplaceId) =>
  invoke<BreakdownRow[]>("collection_breakdown", { dimension, marketplace }),
wishlistBreakdown: (dimension: string, marketplace: MarketplaceId) =>
  invoke<BreakdownRow[]>("wishlist_breakdown", { dimension, marketplace }),
deckValues: (marketplace: MarketplaceId) => invoke<DeckValue[]>("deck_values", { marketplace }),
activityRecent: (limit: number) => invoke<ActivityEntry[]>("activity_recent", { limit }),
```

`ActivityEntry.scope` is one of `"collection" | "wishlist" | "deck"` — the `deck` rows come from
`deck_audit`, carry a `deckId`, and reuse that table's own `kind` vocabulary. `deckId` is `null` on
every `activity` row. TypeScript owns the union; Rust stores strings.

**The widget vocabulary is TypeScript's and appears in no Rust file:**

```ts
export type WidgetKind =
  | "summary" | "decks" | "folders" | "collectionValue" | "wishlistValue" | "activity";
export type BreakdownDimension = "rarity" | "color" | "set" | "finish";
```

`BreakdownDimension` is the one exception that also exists in Rust — as four `match` arms on a
`&str` in each breakdown command, refusing anything else. That is a *fact about SQL columns*, not a
vocabulary about widgets.

That last test is the one that pins the read rule's edge: **a reader who removed every widget must
not be handed the default back on the next launch.** `stored` therefore distinguishes "no row" and
"a row holding a valid document with no widgets", and only the first is the default.

| --- | --- | --- |
| 1 | `summary` | 2 |
| 2 | `decks` | 1 |
| 3 | `activity` | 1 |

`crate::sync::lock_db_read` for the read and `crate::sync::with_write` for the write.
