# Tags Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tags view — its own sidebar entry — that finds cards by Scryfall Tagger's art and oracle tags, for building decks around an art theme or motif.

**Architecture:** Art tags come from a second bulk dataset keyed on `illustration_id`; they get their own five tables and a 951 k-row transitive closure. `oracle_tags.rs` splits into a parameterised engine that both datasets bind to. Tag terms become ordinary `CardFilters` fields compiled to `EXISTS`/`NOT EXISTS`, so the new page reuses `search_cards`, `useCardSearch`, `FilterBar`, sorting and paging wholesale rather than growing a second search stack.

**Tech Stack:** Rust (rusqlite, flate2, serde, tauri 2.11), TypeScript 6, React 19, TanStack Query, zustand, Vitest, Storybook.

**Spec:** [`docs/superpowers/specs/2026-08-20-tags-page-design.md`](../specs/2026-08-20-tags-page-design.md)
**Research:** [`docs/superpowers/research/2026-08-20-scryfall-art-tags.md`](../research/2026-08-20-scryfall-art-tags.md) · [`docs/superpowers/research/2026-08-14-scryfall-oracle-tags.md`](../research/2026-08-14-scryfall-oracle-tags.md)

## Global Constraints

Every task's requirements implicitly include this section.

- **Run `npm install` in this worktree before any suite.** Without it three suites fail on Vite's `fs.allow` and it reads as your regression. See the `worktree-setup` skill.
- **Never run two `npm run verify` at once.** Concurrent runs fake ~18 Rust schema failures.
- **`npm run verify` does not run `cargo fmt --check` or `cargo clippy`.** CI runs both, and they are the only reds reachable from a fully green verify. Run `cargo fmt` and `cargo clippy --all-targets -- -D warnings` in `src-tauri/` before every commit. **Clippy caps a function at 7 arguments.**
- **Follow every parent edge.** Never `parent_ids[0]`, never `child_ids`. 43% of art tags have more than one parent; the graph runs to depth 10. Every graph walk carries a visited set and a missing-id guard.
- **Rust supplies facts; TypeScript draws conclusions.** Nothing in Rust names a category, ranks one tag above another as a *product* decision, or filters the taxonomy down to "the useful part".
- **Nothing may break a launch or a card sync.** Tag refreshes are spawned, best-effort and silent; a failure leaves the previous rows standing and writes the reason to `error_log`.
- **Bad input is never fatal.** An unparseable line is counted and stepped over. A file yielding *no* tags is refused outright and swaps nothing.
- **A prose-only edit routes to neither CI job.** Re-count any list or figure you change, in the same commit.
- **Adding a dependency with permissions means adding its narrowest permission, never `:default`.** This plan adds no dependency.
- **Never install `@types/node`.**
- **Commit after each task** with `feat:` / `fix:` / `chore:` / `test:` / `refactor:`.
- Scryfall User-Agent is `MTGGrimoire/0.1 (+https://github.com/Msgaihede/mtg-grimoire)`. `api.scryfall.com` requires it; `data.scryfall.io` is unmetered and unauthenticated.

- [ ] **Step 4: Add the live and staging table constants**

Beside `ORACLE_TAG_TABLES_SQL` (~line 1803). Two literals, not one with names rewritten — the fence test compares the two shapes and a string substitution would defeat it, exactly as the oracle pair documents.

```rust
/// The four art-tag tables and their watermark, as the v20 step creates them.
///
/// **A parallel set rather than a `kind` column on the oracle tables, because the join
/// column differs**: an art tag is a fact about an *illustration*, so it belongs to the
/// printings carrying that art and to no others. A card with five arts has five
/// illustrations and the dog is in one of them. See the 2026-08-20 research.
const ART_TAG_TABLES_SQL: &str = "
    CREATE TABLE IF NOT EXISTS art_tags (
        slug TEXT PRIMARY KEY,
        -- Scryfall's stable uuid. `slug` stays the key (storage is rebuilt wholesale on
        -- every ingest, so a rename is harmless there) but anything that *persists* a tag
        -- across ingests must be able to notice one. Their docs: 'Do not treat tag slugs
        -- or labels as permanent identifiers […] Use the id field.'
        id TEXT NOT NULL,
        label TEXT NOT NULL,
        description TEXT
    ) WITHOUT ROWID;
    CREATE TABLE IF NOT EXISTS art_tag_parents (
        child_slug TEXT NOT NULL,
        parent_slug TEXT NOT NULL,
        PRIMARY KEY (child_slug, parent_slug)
    ) WITHOUT ROWID;
    CREATE TABLE IF NOT EXISTS art_taggings (
        illustration_id TEXT NOT NULL,
        slug TEXT NOT NULL,
        -- Stored because it is data we were given. Unlike the oracle side this one is read:
        -- art tags use the full scale (median 462 008, strong 5 980, weak 4 495,
        -- very_strong 2 680), where oracle taggings are 99.7 % median and `strong` occurs
        -- exactly once in the whole file.
        weight TEXT,
        -- OMITTED rather than null on ~99 % of taggings, which is a different absence from
        -- `description`'s null and needs a different parse.
        annotation TEXT,
        PRIMARY KEY (illustration_id, slug)
    ) WITHOUT ROWID;
    CREATE TABLE IF NOT EXISTS art_tag_illustrations (
        illustration_id TEXT NOT NULL,
        -- Every tag the illustration holds *and* every ancestor of those tags.
        slug TEXT NOT NULL,
        -- The STRONGEST weight among the direct taggings this row descends from
        -- ('very_strong' > 'strong' > 'median' > 'weak'). Resolved once here because a
        -- closure row can be reached from several taggings that disagree: a printing whose
        -- `dog` tagging is weak but whose `hound` tagging is strong is not a weak match,
        -- and deciding that per row at read time would be work on every keystroke.
        weight TEXT NOT NULL,
        PRIMARY KEY (illustration_id, slug)
    ) WITHOUT ROWID;
    CREATE TABLE IF NOT EXISTS art_tag_meta (
        id INTEGER PRIMARY KEY CHECK (id = 1),
        etag TEXT,
        updated_at TEXT,
        ingested_at INTEGER NOT NULL,
        checked_at INTEGER NOT NULL,
        tag_count INTEGER NOT NULL,
        tagging_count INTEGER NOT NULL
    );";

const ART_TAG_STAGING_SQL: &str = "
    DROP TABLE IF EXISTS art_tags_staging;
    DROP TABLE IF EXISTS art_tag_parents_staging;
    DROP TABLE IF EXISTS art_taggings_staging;
    DROP TABLE IF EXISTS art_tag_illustrations_staging;
    CREATE TABLE art_tags_staging (
        slug TEXT PRIMARY KEY,
        id TEXT NOT NULL,
        label TEXT NOT NULL,
        description TEXT
    ) WITHOUT ROWID;
    CREATE TABLE art_tag_parents_staging (
        child_slug TEXT NOT NULL,
        parent_slug TEXT NOT NULL,
        PRIMARY KEY (child_slug, parent_slug)
    ) WITHOUT ROWID;
    CREATE TABLE art_taggings_staging (
        illustration_id TEXT NOT NULL,
        slug TEXT NOT NULL,
        weight TEXT,
        annotation TEXT,
        PRIMARY KEY (illustration_id, slug)
    ) WITHOUT ROWID;
    CREATE TABLE art_tag_illustrations_staging (
        illustration_id TEXT NOT NULL,
        slug TEXT NOT NULL,
        weight TEXT NOT NULL,
        PRIMARY KEY (illustration_id, slug)
    ) WITHOUT ROWID;";

/// The four live art-tag tables and their staging twins, paired — [`ORACLE_TAG_TABLES`]'s
/// rule: the swap, the cleanup and the shape-comparison test all name the same four.
pub const ART_TAG_TABLES: [(&str, &str); 4] = [
    ("art_tags", "art_tags_staging"),
    ("art_tag_parents", "art_tag_parents_staging"),
    ("art_taggings", "art_taggings_staging"),
    ("art_tag_illustrations", "art_tag_illustrations_staging"),
];
```

        let tx = conn.unchecked_transaction()?;

- [ ] **Step 3: Implement the weight ordering**

In `tags/art.rs`:

```rust
/// Scryfall's four weights, weakest first. Their definitions, from `docs/api/tags`:
/// `weak` "a minor detail or background element", `median` "a normal tagging",
/// `strong` "a primary focus", `very_strong` "exemplary".
///
/// Bulk data is lowercase snake; Tagger's GraphQL returns the same values uppercase. This
/// app only ever reads bulk data, so lowercase is the whole vocabulary.
pub const WEIGHTS: [&str; 4] = ["weak", "median", "strong", "very_strong"];

/// The stronger of two weights. **An unrecognised value ranks below every known one** —
/// a weight this build has not heard of must never silently outrank `very_strong`, which
/// is the direction that would quietly promote junk into a filtered result.
pub fn stronger<'a>(a: &'a str, b: &'a str) -> &'a str {
    let rank = |w: &str| WEIGHTS.iter().position(|x| *x == w).map(|i| i as i32).unwrap_or(-1);
    if rank(b) > rank(a) { b } else { a }
}
```

Then in `tags/mod.rs`'s closure builder: when `ds.carries_weight`, each closure row's weight is `stronger` folded over every direct tagging that reaches it. A row reached only through ancestry inherits the weight of the tagging that produced it.

- [ ] **Step 5: Write the fixture**

`src-tauri/fixtures/art-tags-sample.jsonl` — one Tag object per line, no outer array. It must contain, because each is a rule the ingest has to honour:

1. A tag with **two parents** (43% of the real file).
2. A **grandchild**, so the closure has to walk more than one level.
3. A tagging with **`annotation` omitted entirely** (not null) and one with it present.
4. Two taggings of the same illustration under a child and its parent with **different weights**, so the resolution in Step 3 is exercised end to end.
5. A `"description": null` line.
6. A line that is **not valid JSON**, and a line that is valid JSON but not a tag object — both must be counted in `skipped_lines` and stepped over.
7. A tag whose `parent_ids` names an id **the file never defines** — counted in `dangling_parents`, not fatal.

Every line's `"type"` is `"illustration"` and every tagging key is `illustration_id`.

- [ ] **Step 3: Walk the §6 checklist over CDP**

`docs/reference/live-ui-verification.md` is the harness contract. Traps that have each cost a session:

- **Use PowerShell for `cdp.mjs`** — Bash refuses the eval as unverifiable. Avoid nested quotes and `$`.
- **`hover --rest 200` before `click`** — a cold pointer makes `click` a no-op that still prints "clicked".
- **Split click-then-read into two evals** — reading in the same eval answers about the frame before React re-rendered, so a working control reads as broken.
- **Wrap every binding in an IIFE** — `cdp.mjs eval` shares one scope, so a top-level `const` outlives its command.
- **`cdp.mjs key` for Escape**, never `window.dispatchEvent` — a synthetic Escape collapses capture into registration order and reports a false regression.
- **Put `innerWidth` and `scrollWidth` in the same eval as any rect** — the window can resize between passes and a wide desk reads exactly like an overflow.
- **`cdp.mjs shot` can exit 0 and write nothing.** `Test-Path` it; fall back to rect numbers rather than burning the pass.
